# 「模拟流修仙」全网盘点 — 统一字段口径

通道 1 派单，通道 2–5 并行抓取。**本文件由通道 1 维护，其余通道只读，不要改。**

调研目的：把「主角靠模拟／推演反复试错」这一类修仙玄幻小说在各平台的存量、体量、题材写法摸清楚，给本仓《杂役模拟三千世》做同题对标。**这是外部作品调研，与 `01-设定/`、`02-大纲/` 的本书设定无关，不得据此改本书任何设定。**

## 1. 收录判据（两个条件都要满足）

**条件 A — 模拟属性**：书名、标签、简介三处中至少一处命中下列任一词：
模拟、模拟器、推演、演算、沙盘、预演、重开、无限重生（限定为「同一段时间反复重来」义）、人生模拟。

**条件 B — 修仙属性**：分类或标签属于 仙侠／修真／玄幻／东方玄幻／洪荒／宗门 一类，或简介中出现 修仙、修真、炼气、筑基、金丹、元婴、宗门、灵根、大道。

只满足 A（都市模拟、足球模拟、种田模拟）**不收**，但请单列进 `nearMiss` 数组，一行一条，注明为什么被排除——边界样本对结论同样有用。

### 「重开」是词形陷阱，命中它必须回原句看词义

括号里那个「同一段时间反复重来」的限定**对「重开」同样生效**，不是只管「无限重生」。通道 3 在塔读池里命中「重开」4 本，逐条回原文后**全数排除**：《仙凡道记》「天地重开，万族尽殁」、《乱世仙途》「天劫又至，乱世重开」、《吾有一卷君敢观否》「通天欲重开世界」、《修仙从学习火焰呼吸开始》「重开登仙之门」——全是开天辟地／重启仙路义。**词形命中 4，词义命中 0。**

这个词在修仙题材里本来就有一个高频的旧义，所以它的假阳性率不是「偶尔」，可能是「大多数」。命中「重开」的书一律回原句判词义，判不了就进 `nearMiss` 并附原句让人可推翻；不要只凭词表命中就收。同理适用于「沙盘」「演算」「预演」这几个弱词——「模拟器」「人生模拟」这类强词不用。

### 「单次重生」不算「反复重来」（2026-09-09 裁定）

括号里那句「同一段时间**反复**重来」，**「反复」是定义性的，不是修饰**。只重生一次的书是**重生文**——另一个成熟品类，主角只有一次机会、不能试错；而本次调研要盘的是「靠死过一次换来的信息回到现实里做对的选择」那个机制。两者的读者体验、爽点结构、章节节奏都不同族。

判例：飞卢《仙尊重开记》「因上一世被杀害……又重开了」，只重开一次，**剔入 `nearMiss`**。对照保留的：《重生之人有重开日花无再少年》「我已重开万世……第一万次重开」、《漏洞都是漏洞，重开》「任何选择都可以重来，只需要付出一点点代价」、番茄《死回仙尊》「他死一次就能原地复活」——这些都带「万世／一万次／无限／死一次就」这类**反复**的记号。

**这条裁定只会让更多书被剔，不会让已剔的回来**，所以不必重审已剔除的那些（七猫 3 本、飞卢 18 本都是开天辟地义，与本条无关）。要复查的只有**已保留的「重开」书**。

### 「沙盘」命中得很准，但它指向的是另一个机制（2026-09-09 裁定）

**「沙盘」不是词形陷阱**——这一点和「重开」正相反。通道 3 逐本核过飞卢／纵横那 28 本，**零误命中**，没有一本是「将军盯着沙盘看了半日」那种景物义。词形判得很准。

**问题出在别处：沙盘流和模拟流是两个相反的机制。**

| | 模拟流（本次要盘的） | 沙盘流 |
| --- | --- | --- |
| 方向 | **向内**重活自己这一生 | **向外**造一个世界看它演化 |
| 时间线 | 回滚 | 不回滚 |
| 主角 | 自己反复重来 | 自己不重来，是造物主／观察者 |

最干净的证据是《穿越创世沙盘，开局荒古之体！》：主角发现自己是**被关在别人沙盘里的居民**——沙盘在那本书里根本不是他手里的工具，他是被模拟的那一方。量化旁证也对得上：这 28 本字数中位数只有 **2.7 万字**、21/28 不足 5 万字，高频标签是爸文／位面／种田／直播／网游，与模拟流的系统／重生／升级练功完全不是一族。

**裁定：收录不变，分析必须分开。**

- **不给「沙盘」加限定义、不改条件 A 词表。** 理由：它不像「重开」那样词形不准，按现行判据这 28 本就是合格的；改词表要回溯重审全部交付，且会丢掉一批本身合格的样本。
- **合并与成稿时把「仅靠沙盘入选」的书作为独立亚型单列，同题对标排除它们。** 不排的后果是具体的：28 本非同题的小体量书进分母，**字数中位数与标题句式两项结论都会被带偏**。
- 一句话口径，可以直接抄进成稿：**「沙盘」在本语料里几乎全是真阳性，但它指向的是「造世界看它演化」的沙盘流，而非「把自己这一生反复重来」的模拟流；两者共用一个词，可迁移的写法几乎为零。统计可以合在一起，对标必须分开。**

### 条件 B 的「简介兜底」是给分类没标好的修仙文用的，不是给提到修仙二字的书用的

条件 B 允许「或简介中出现 修仙、修真、炼气…大道」，这一条的用途是捞回**分类标错、但主线确实是修仙**的书。它不是用来收「某一章／某一期节目的题材碰巧是修仙」的书。

判例（通道 2 报上来，通道 1 裁定）：番茄《让你拍节目，你让项羽撕秦始皇？》分类是都市脑洞／都市／系统／穿越／搞笑轻松，命中处是简介里一行节目单「【第六期·修仙模拟之战】」。按字面它过 B，**裁定降为 `nearMiss`**——它是综艺脑洞文，修仙是其中一期的题材，正属第 1 节开头那句「只满足 A（都市模拟…）不收」。判不准的时候问一句：这本书的**主线**是不是修仙；不是就进 `nearMiss` 并附原句，让人可推翻。

另记一个还没造成损失的风险点（通道 2 审计）：B 词表里的**「大道」是宽词**，「大道理」「大道上」都含它。番茄主池因为全部靠分类满足 B，这个风险被整个掩盖住了；它逐条摊开所有「仅靠简介词入选」的书，实测 0 本靠「大道」单独成立。别的通道如果有靠简介兜底入选的书，这一条要单独核。

## 2. 记录字段

每本书一条对象，字段名严格照抄，缺失写 `null`，不要自造字段名，也不要改大小写。

```json
{
  "platform": "fanqie",
  "platformBookId": "7658332715577527358",
  "title": "书名原文",
  "author": "作者名原文",
  "url": "书页完整 URL",
  "wordCount": 1980000,
  "chapterTotal": 830,
  "status": "连载",
  "categories": ["东方仙侠"],
  "tags": ["模拟器", "宗门", "单女主"],
  "abstract": "简介全文，保留原换行为 \\n，不要截断",
  "popularity": { "metric": "在读", "raw": 2092060 },
  "score": null,
  "firstPublishDate": "2024-03-11",
  "lastUpdateDate": "2026-08-30",
  "simEvidence": { "matchedIn": ["title", "abstract"], "keywords": ["模拟"] },
  "openingHook": "第一章前 200 字（能免费拿到才填，拿不到写 null，不要为此登录或绕付费墙）",
  "collectedAt": "2026-09-08T13:00:00Z",
  "source": "抓到它的那个榜单页/搜索页 URL"
}
```

口径说明，容易各写各的就在这几条：

| 字段 | 口径 |
| --- | --- |
| `wordCount` | **一律换算成「字」的整数**。平台显示「198.5万字」要写 `1985000`，不要留字符串 |
| `status` | 只允许 `连载` / `完结` / `unknown` 三个值 |
| `popularity.metric` | 各平台口径不同，**不要强行折算**：番茄填 `在读`，起点填 `推荐票` 或 `收藏`，七猫填 `热度`，飞卢填 `点击`。`raw` 存原始数字 |
| `firstPublishDate` / `lastUpdateDate` | 一律 `YYYY-MM-DD`。只拿得到「3天前」这类相对时间就折算成绝对日期 |
| `simEvidence.matchedIn` | 只能是 `title` / `tag` / `abstract` 的组合，是判据留痕，**不许留空** |
| `abstract` | 全文，不截断。它是后续分析同质化写法的主要输入 |

| 通道 | 平台 | 输出文件 |

文件结构：

```json
{
  "meta": {
    "channel": 2,
    "platforms": ["fanqie"],
    "status": "ok",
    "collectedAt": "...",
    "entryPoints": ["用过的榜单/搜索页 URL"],
    "notes": "抓不到的字段与原因"
  },
  "books": [ /* 上面的记录对象 */ ],
  "nearMiss": [ { "title": "...", "url": "...", "reason": "模拟但非修仙：都市赛车" } ]
}
```

`meta.status` 三个值：`ok` 正常交付、`partial` 部分字段或部分站点受阻、`blocked-by-policy` 因 robots 或反爬整站放弃。**这个字段是通道 3 撞墙后加出来的**，作用是让合并脚本机器判别「这个空文件是阻断，不是没开工」——两者在报告里的含义完全不同，前者是结论，后者是待办。合并脚本不对 `meta` 做白名单校验，多写字段不会被退回。

抓取脚本放 `.scrape/sim/ch{N}_*.mjs` 或 `.py`，**文件名带自己的通道号**。日志写 `.scrape/sim/ch{N}.log`。

**不要碰别的通道的文件，也不要碰 `.scrape/` 根目录下已有的任何文件**（`fq_books.json`、`lib.mjs` 等是既有资产）。`lib.mjs` 可以 `import`，只读不改。

## 4. 抓取纪律

沿用 `.scrape/lib.mjs` 里已经固化的做法，不要另起一套：

- **请求间隔 ≥ 1 秒**，用 `lib.mjs` 的 `sleep`（Windows 上 `setTimeout` 会提前触发，那里已经绕过了）
- **403 / 429 / HTTP 200 空 body 一律退避 60 秒**，不做原地重试风暴。空 body 是番茄的软限流，当成硬失败会白丢一本书
- **加一条「页面异常短就当失败」的断言**，阈值按站定（几百字节量级）。理由见下
- 只抓公开页面：榜单页、分类页、搜索页、书籍详情页。**不登录、不绕付费墙、不抓正文章节内容**（`openingHook` 只取免费试读页面公开可见的前 200 字，取不到就写 `null`）
- `robots.txt` 明确禁止的路径不抓，记进 `meta.notes`
- 抓到的原始 HTML 若要留档，放 `.scrape/sim/raw/ch{N}_*.html`

### 最贵的一类失败是不报错的那一类

番茄的空 body、飞卢的 357 字节过渡页，是同一件事的两个样子：**HTTP 200、不抛异常、不返空、解析器照常跑完**，只是解出来的每个字段都是 `null`。通道 5 第一轮就这么拿到 46 本字段全 `null` 的书——**如果没人去看那批数据，它会一路混进最终报告**。

飞卢那张页明文写着 `C3VK` cookie 然后自跳转，存下 cookie 原样重取即可（浏览器本来就这么做，不涉及解混淆）。但真正要记住的不是这个具体处理，是那条断言：**响应长度明显小于同类页面时，当失败处理，不要交给解析器。** 解析器对着一张跳转页只会安静地返回一堆 `null`，而 `null` 在本次口径里是合法值——两层「合法」叠起来，错误就没有任何出口了。

**Node 脚本的一个坑，四条通道都会踩**：仓库路径带中文（`D:\VScodeSpace\小说天团`），`import.meta.url` 是 percent-encoded 的（`小说天团` → `%E5%B0%8F%E8%AF%B4%E5%A4%A9%E5%9B%A2`）。拿 `new URL(import.meta.url).pathname` 当路径用，会静静地写到一个不存在的目录去，报 `ENOENT` 且路径里全是 `%E5`。必须解码：

```js
import { fileURLToPath } from "node:url";
const DIR = fileURLToPath(new URL(".", import.meta.url));
```

通道 1 写 `ch1_merge.mjs` 时当场踩到并修掉了，写在这里省你们四份各踩一次。

**准确的边界是「不要取 `.pathname`」，不是「不要用 `import.meta.url`」**（通道 3 实测补充）：把 URL 对象**直接**交给 `fs.writeFileSync` / `fs.mkdirSync` 是安全的，Node 会自己 percent-decode——他改之前的版本就是这么写的，12 个探活 HTML 全部正确落盘，没报 `ENOENT`。炸的只有手动取 `.pathname` 拼字符串这一条路。写成「禁用 `import.meta.url`」会让人去改本来就对的代码。

### 自检断言要回源取证，不要用字符串启发式

通道 5 的 `ch5_validate.mjs` 起初把 `abstract.endsWith("...")` 断言为「被截断」。它确实逮到了真问题（飞卢 46 本全是列表页的 64–78 字截断版），但这个断言两头都不准：三本《开局推演雷法千鸟，竟然被姐姐直播曝光了》《洪荒之推演万法》《穿越创世沙盘，开局荒古之体！》的省略号是作者自己在简介里打的，是误报；而站方**直接切断、不留省略号**的那种截断，它一条都抓不到。

正确做法是回源取证：拿 `.scrape/sim/raw/` 里存档的书页 HTML，与正文区（飞卢是 `Box1`）逐字比对，一致即站方原文。通道 5 照此改完，全表 0 问题，且整个核验零网络请求——存档 HTML 本来就是为这种时刻留的。

**一般化到所有通道**：凡是「这个字段看起来不对」的自检，判据要落在可复验的源上（存档 HTML、接口原始返回），不要落在成品字符串的形状上。形状类断言在这种数据上既漏又误，而误报比漏报更贵——它会让人去修一个本来没错的地方。

**但存档本身也要先验，否则这条规则会反过来咬人。** 通道 5 隔一轮又踩了一次，方向相反：它以为 `raw/` 里多出来的 24 份 `ch5_faloo_{id}.html` 是书页存档、可以零请求补数据，逐份打开才发现全是 357 字节的 C3VK 过渡页——文件名对得上、HTTP 200、解析器照常跑完，解出来每个字段都是 `null`。**拿一张过渡页去「回源取证」比字符串启发式更糟：它产出的是一份看起来有据可查的假数据。** 所以取证的第一步是验存档本身（长度阈值按站定，飞卢用的是「< 5000 字节当失败」，与第 4 节那条「页面异常短就当失败」是同一条断言的存档侧），验过了才谈逐字比对。

这两次是同一件事的两面：**`null` 与「合法字符串」在本次口径里都是合法值，所以任何一层不报错的失败都能一路走到成稿。** 每一层都要有自己的断言。

## 5. 目标量与优先级

原定每个通道 40–80 本。**2026-09-08 通道 1 拆掉了上限，改为「凡过判据的全收」**，判据不满足的一本都不收。

改的理由很具体：七猫搜索 API 与飞卢列表页**单条就带回简介全文、字数、分类、更新时间**，也就是说过滤阶段的记录已经在手里，**多收一本的边际请求数是零**。这种时候卡数量上限是白丢样本。反过来，靠逐本翻详情页才能补齐字段的站（塔读这类），仍然按「先头部、宁少勿滥」走。

先抓头部：各平台的仙侠／玄幻榜单前列 + 站内搜「模拟」「模拟器」「推演」的前几页。头部样本对「这个题材现在长什么样」的解释力，远高于尾部凑数。

### 只搜模拟词会系统性漏掉一整个亚群，必须补一轮反向召回

**做法**：第一轮搜模拟词（条件 A 的词表）拿到池子；**第二轮反过来搜修仙词**（杂役／筑基／金丹／元婴／灵根／长生／宗门／炼气／化神／仙门／凡人修仙／苟道），再用模拟词过滤这个池子。

**为什么非做不可**：搜「模拟」时，那些**模拟只写在简介里、没进书名**的书排不上来——搜索引擎的相关度是按标题权重给的。漏掉的恰好是「模拟当里子而不当招牌」的那一类。

**实测代价与收益**（通道 4，七猫）：第三轮 83 次请求扫 1230 条，总量只 +7%（86 → 92 本），但**「仅简介命中」这个亚群从 5 本翻倍到 11 本**。也就是说，要回答「模拟到底是卖点还是里子」这个问题，**一半样本是这一轮才有的**——不补这一轮，那个维度的结论直接站不住。

站内搜索被明禁的站（塔读）走分类浏览，本来就等价于反向召回，不必额外做。

拿不到的字段写 `null` 并在 `meta.notes` 里说明原因，**不要猜，不要填占位值**。一个编出来的数字比一个 `null` 贵得多。

### 自己解析 robots 的，必须先把全角冒号归一成半角

书旗的 `robots.txt` 里那五条 `Disallow` 用的是**全角冒号**（`Disallow：/about/`）。全角冒号不是合法 robots 语法，**严格解析器会把这五行整行忽略，解析结果变成「该站没有任何限制」**。

这个 bug 危险的地方在于它切的是**放宽**的方向：它不报错、不抛异常、不返回空，只是安静地把站方的限制变没。通道 3 第一遍就中了，发现后把全角冒号归一成半角重跑，按站方**意图**让那五条生效，没有钻这个格式空子。

判据是：**robots 解析出现歧义时，往严的一侧倒。** 站方写错格式不等于站方放开限制。

**别被文件名骗了**：`.scrape/` 根目录下那批 `ch4_zh*.py`（`ch4_zhpeek` / `ch4_zhfetch` / `ch4_zhauthor` / `ch4_zh_final`）里的 `zh` 是**纵横**（`book.zongheng.com`），不是知乎。通道 1 在派单里把它误当成知乎资产，由通道 4 现场纠正。知乎侧本仓没有任何存量，从零开始。
