# agents

给 agent 会话看的操作约定。总入口与红线见 [AGENTS.md](../AGENTS.md)，开一个新窗口怎么起手见 [parallel_prompt.md](../parallel_prompt.md)，通道与消息见 `.cursor/rules/idp-mcp-messenger.mdc`，平台写法见 [`fanqie-webnovel-writing/SKILL.md`](../.cursor/skills/fanqie-webnovel-writing/SKILL.md)。

本目录只写这几处**都没有**的东西：仓库层面的权威边界、问题往哪登记、流程的落差、多个通道共写一棵树的做法。

> **v2 状态（2026-09-26）。** 本目录现行操作口径已对当前 v2 文件复核；保留的云昭、赵堂、老周、谢无咎、青玄宗等具体事故属于 v1 历史，不引用它们的名字、数字或机制。卷四至卷八当前是**规划入口，逐章表未完成，不能直接写正文**；其他卷也须逐条核对顶部状态、逐章三栏及所需机制。仓库已有 Git，提交由通道 1 收口；共享工作树的备份、取证与分工规矩继续有效。门禁结果区分已确认硬错误与只列不判，反验使用 `workflow.md` 的临时假章方案。

新人按 `domain.md` → `workflow.md` 的顺序读，其余三份用到再翻。

**两条最容易踩、后果最贵的，先记住：**

1. **全库写回类命令仍不得单方面跑，跑前核对已有改动的归属。** 「扫当前树再写回去」的都算——批量替换、批量重排章号、批量回填字数；先看 `git status` 与相关差异，在通道里约定谁跑、什么时候跑并保留工作树快照，跑完人工过一遍。整份文件回退可能连带别人的未提交改动。见 [workflow.md 的取证](./workflow.md#取证这东西是谁什么时候改的)。
2. **让步顺序是「机制 → 其余设定 → 大纲 → 正文」**：正文让给大纲，大纲让给设定，设定里其余各份让给 `02-模拟器机制.md`（它是地基）。设定不再「封存定稿」，**改要走裁决记录**——先 `broadcast` 提请全组终裁，定了再改，并把「怎么定的、为什么不是另一种定法」写进该文件末尾的裁决记录。见 [domain.md 的冲突裁定](./domain.md#冲突按什么顺序裁) 与 `AGENTS.md`「改文档」表。

**本目录六份文件末尾各有一张修订记录表。** 改了内容就加一行——2026-09-10 之前这棵树没有 git，那张表曾是唯一的历史；现在 git 记的是改了什么，修订记录记的是为什么，两样都要，理由见 [workflow.md 的取证](./workflow.md#取证这东西是谁什么时候改的)。
