**两条最容易踩、后果最贵的，先记住：**

1. **全库写回类命令仍不得单方面跑，跑前确认工作区干净。** 「扫当前树再写回去」的都算——批量替换、批量重排章号、批量回填字数；先 `git status` 看工作区是不是干净的（别人未提交的改动会被你一起写坏），再在通道里约定谁跑、什么时候跑，跑完人工过一遍。有 git 之后写坏了能回退，但回退的是整份文件，会连别人那一半一起退掉。见 [workflow.md 的取证](./workflow.md#取证这东西是谁什么时候改的)。
2. **让步顺序是「机制 → 其余设定 → 大纲 → 正文」**：正文让给大纲，大纲让给设定，设定里其余各份让给 `02-模拟器机制.md`（它是地基）。设定不再「封存定稿」，**改要走裁决记录**——先 `broadcast` 提请全组终裁，定了再改，并把「怎么定的、为什么不是另一种定法」写进该文件末尾的裁决记录。见 [domain.md 的冲突裁定](./domain.md#冲突按什么顺序裁) 与 `AGENTS.md`「改文档」表。

**本目录六份文件末尾各有一张修订记录表。** 改了内容就加一行——2026-09-10 之前这棵树没有 git，那张表曾是唯一的历史；现在 git 记的是改了什么，修订记录记的是为什么，两样都要，理由见 [workflow.md 的取证](./workflow.md#取证这东西是谁什么时候改的)。
