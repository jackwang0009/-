# 问题登记在哪

本仓没有工单系统，也没有版本控制。发现的问题分五个通道走，选错通道的后果是问题被记在一个没人会再看的地方。

## 五个通道

| 通道 | 存活期 | 装什么 |
| --- | --- | --- |
| 各设定/大纲文件末尾的**裁决记录** | **永久** | 一条争议最后怎么定的，以及**为什么不是另一种定法** |
| `01-设定/05-术语与命名表.md` 第九节**冲突清单** | **永久** | 跨文件不一致：两个文件对同一件事说了两套 |
| `04-审校/NNNN-NNNN.md` | **永久** | 已经查过的结论，以及主笔的回执 |
| 章节元信息的 `待确认:` 字段 | 一章 | 主笔当场遇到的设定分歧，**不许自己拍板** |
| idp-mcp 消息与任务 | 一次 | 终裁的宣告（`broadcast`）、点对点协调（`send_to_session`）、「谁去把它改掉」（`dispatch_task`） |

判据：**结论进裁决记录，跨文件不一致进冲突清单，查过的进审校记录，当场拿不准的进元信息，动作进任务。** 一个问题通常会依次经过好几个通道，不是几选一。

## 裁决记录：本仓最重要的一个惯例

设定文档与每一卷卷纲末尾都有一节裁决记录，全部标着 `✅ 已清零`。它长这样：

```markdown
- [x] ~~1100 章的分卷比例 / 卷一要不要拉到 80 章~~ **已定：维持 60 章，分卷总表一个字不动。**
  卷一是全书最脆弱的一段——读者刚点进来，沉没成本为零，随时可以划走。60 章 ≈ 13.2 万字，
  早已越过 8 万字那道推荐评估关卡；再加 20 章等于在最危险的窗口多押 4.4 万字的低强度内容，
  追读率的损失大于杂役院多写二十章的收益。
```

三件事缺一不可：**划掉原问题**、**写明定成什么**、**写明为什么不是另一种定法**。

第三件是全部的价值所在。术语表第九节 ② 那条在金丹和元婴之间来回改了三版，第四版之所以能定下来，靠的就是前三版为什么不行都还记着。裁决记录自己写着这句话：**「保留完整记录，是为了让后来写正文的人知道每一条是怎么定的、以及为什么不是另一种定法——不要因为『看起来还能改』就回头改。」**

**已否决的方案不要删，标成存档。** `08-卷八-三千世.md` 第十节那个备选结局（保留化神、三千世共存）被否了，但整节留着并写明「切换口关闭，本节仅存档」。删掉它，下一个人会重新提一遍同样的方案。

**改完内容还要更新该文件末尾的修订记录表。** 这棵树没有 git（见 [workflow.md 的取证](./workflow.md#取证这东西是谁什么时候改的)），修订记录是唯一的历史。

### ⚠️ 裁决记录是一本**独立的欠账本**，查审校单查不到它

**「这一章的必改清完了没有」不能只翻 `04-审校/` 的必改表。** 裁决记录里那些**已经裁完、但正文还没落地**的条目，**不在任何一张审校单的必改表里**——审校单记的是审校报出来的问题，裁决记录记的是全组拍板的结论，**两本账各记各的，逐单查是查不到的**。

**这条是 2026-09-07 用一次实事换来的**：有人判定 0001–0018 的「已知必改全清」并据此把七章推进「已审校」，方法是逐张翻审校单——干净。可同一天的终裁二（「他扫的那一段不给级数」）**只落了审校文件那一半，正文那一半一处没落**，全段还躺着十几处「三千六百级」。**四章因此被推早了。** 那十几处从头到尾没有出现在任何一张审校单上。

**所以判「清完了没有」要翻三本，不是一本：**

| 本 | 在哪 | 它记的是 |
| --- | --- | --- |
| 审校单 | `04-审校/` 各段文件的「必改」表 | 审校报出来的 |
| **裁决记录** | 各设定文档与卷纲末尾、术语表第九节冲突清单、`04-审校/终裁-*.md` | **全组拍板的结论**——**裁完不等于落完** |
| 元信息 `待确认` | 每章文件头 | 写的时候拿不准、留给后面定的 |

**给裁决记录写条目的人也有一半责任**：**下裁定时把「正文侧要动哪几处、归谁落」一并写进去**，否则那条裁定就只活在设定层，正文永远等不到人来改。终裁二当时的【连带】只点了一章，**漏掉了「全书还有多少处」这一问**——而正是这一问决定了它是一句话的活还是十几处的活。

> **这也是「打包改、不分章派」那条的由来**：同一条裁定散在十几处时分章派，必定出现**改了一半**——而**「改了一半」比「全都没改」难发现得多**，因为抽查很容易正好抽到已经改对的那几处（[workflow.md 记的那 266 个直角引号](./workflow.md#门禁)就是这个形状）。**收口时全树 grep 一次那个词，剩下几处、分别在哪，写进回执**——这是防「改了一半」唯一可靠的手段。

## 冲突清单：跨文件不一致专用

跨文件不一致不属于任何单个文件，所以它有专门的位置：[`01-设定/05-术语与命名表.md` 第九节](../01-设定/05-术语与命名表.md)。

现有 11 条的格式是一张总表加逐条原始记录，每条带**两个文件的原话**、按要紧程度分「高：不定就会写崩 / 中：会影响后面几卷的解释 / 低：取值不一致挑一个就行 / 已消解」。

两条做法：

- **报冲突要带两边的原话，引小节名不引行号。** 引不出原话的不要报。
- **不要自己去改别人的文件。** 术语表自己写着这一条——那个文件可能正被另一条通道写着。写进清单，`send_to_session` 通知责任通道。

**「不矛盾，但两个值」也要登记。** 赵堂的年龄在世界观里是「四十七岁」、在人物档案里是「四十来岁」——不矛盾，但下一个人拿哪个？定成 47 就完了，但不定就会一直有人来问。

## `04-审校/`

**一段一个文件**，和正文章段对齐：`04-审校/0001-0010.md`。同一段复审不新建文件，在末尾追加「第 2 轮」小节。格式（结论 / 必改 / 建议 / 可忽略 / 主笔回执五节）和定位写法由 [`04-审校/README.md`](../04-审校/README.md) 第二节定，分级口径见 [triage-labels.md](./triage-labels.md)。

单章的审校结论不单独开文件，追加到所在段那一份里。1100 章开 1100 个文件，等于没记。

### 「可忽略」那一节不要省

它列出你专门查过、确认不用改的地方，决定了下一轮审校能不能少走一遍。省掉它，下一个人会把同样的交叉比对重做一次，还可能得出相反结论。

这一点在本书比在别的书更要紧：**要比对的既有事实每写一章就多一层**，而这本书要写 1100 章。第 36 章那一轮是全量四道加通读，九万字做得动；到卷三三十万字时，如果每一轮都从头比一遍，审校会先于主笔崩掉。

### 主笔回执是审校流程的闭环

审校**只出清单，一个字都不动 `03-正文/`**（`04-审校/README.md` 第四节，三条理由）。所以每一条必改都要有回执：改了 / 没改 + 一句为什么。**没有回执的必改等于没提。**

## 章节元信息的 `待确认`

主笔写到一半发现设定里查不到的东西——一个数、一个称呼、一条规矩——**不许自己编，也不许停下来等**。填进本章元信息的 `待确认`，继续写，收工时回报派单通道。

已有一个写得很好的样板，`0031-一个名额.md`：

```
待确认: 无（2026-08-27 裁定：采纳，已回填 03-世界观.md 1.2。不冲突——这一改不是推翻
「名额由管事定」，恰恰是它的结果：赵堂月考丢了脸，云昭册子上又记着一功……）
```

**注意它裁完之后没有把这一格清空，而是把裁决过程留在了原地。** 这一格是给下一个改这一章的人看的，不是给自己看的。

## idp-mcp 消息与任务

| 形状 | 用 |
| --- | --- |
| 全组宣告一条终裁 | `broadcast` |
| 点对点协调地盘、问一句话、通知责任通道 | `send_to_session` |
| 「谁去把它改掉」 | `dispatch_task`，`toChannel` 指定；省略则自动挑一条空闲通道 |
| 回报进度与交付 | `report_task`（`working` / `done` / `failed`） |
| 盘一遍在飞的活 | `query_tasks` |
| 多步有依赖、想让全组看见进度 | `flow_create` + `flow_start_step` / `flow_complete_step` |
| 一段活要跨会话续做 | `save_progress` / `load_progress` |

**任务本身就是登记，不用再往文件里抄一遍。**

**派单里的章段就是锁**（`03-正文/README.md` 第五节），不另设登记文件。同一段章号不要派给两个通道。

**`dispatch_task` 的 `context` 要写清做什么和不做什么。** 大纲条目交给主笔时必须带上本章**不许提前出现的人和词**——第 1–30 章不许有「仙盟」「魔门」，本卷不许说破的真相各卷卷纲都单列了一节（比如卷三「老周那件事的定稿版，本卷一个字都不许说破」）。漏了这一句就等于放任提前泄底。

**`report_task` 的 `result` 里列章号、实计字数、`待确认` 有没有。** 不要只写「写完了」——下一个人接手时拿不到任何东西。

**终裁必须走 `broadcast`，而且落地要写进裁决记录。** 只广播不落地，下一轮没人知道当时定了什么；只落地不广播，别的通道会继续按旧口径写。

## 什么不进任何通道

**别人正在改的文件里的问题**，以及**你没打开源文件确认过的问题**。

第一类会在对方那一轮里自己消失，报了只会驱使他去看一个正在变的地方。第二类是纯粹的负收益——[domain.md 提到的那次误报](./domain.md#冲突按什么顺序裁)里，审校报了两个文件打架，打开一看真正错的是第三个文件，差点让人去改一处本来没错的地方。
