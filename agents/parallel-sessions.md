# 多个通道共写一棵工作树（v2 · 2026-09-26）

本仓的常态就是这个形状：几个 Cursor 窗口 = 几名成员，同时开在**同一个工作目录** `D:\VScodeSpace\小说天团` 上，各绑一条 `idp-mcp-N`（通道配在 `.cursor/mcp.json`，有几条以那个文件当场为准）。单人单会话不必读本文。

写下反面教材是有意的：只写成功经验的方法论，下一个人复现不出来。**本文 2026-09-11 之前的具体章号、文件名和人物例子均为 v1 历史**，不作当前正文、设定或任务依据；现行操作按所引 v2 文件核对。

## 地盘已经分好了，越界前先说一声

**一个目录一个写入方。** 归属表在 [domain.md](./domain.md#目录归属)——设定 `01-`、大纲 `02-`、主笔 `03-`、审校 `04-`、调研 `docs/`。

这一条不是靠锁维持的，是靠事先分派维持的。**会话之间无法可靠地协商出地盘：每个会话只看得见自己的任务。**

越界之前在通道里说一声（`send_to_session`），对方让位再动。

**通道数量本身要克制。** 配了几条通道，不等于几个人都得同时在写。空转的只读会话会互相仲裁——同一件事套四层，没有一层该发。

### 主笔的地盘要细到章号

**`03-正文/` 整个目录不是一个地盘，一段连续章号才是。** 派单里的章号区间就是锁（`03-正文/README.md` 第五节），一次最多 10 章，不另设登记文件。

同一段章号不要派给两个通道。这是唯一一道真正拦得住撞车的闸——**本仓没有文件锁，`set_channel_lock` 锁的是消息队列，不是文件。**

**领段时连带读上一段的最后 2 章**，你这段的第一章要接住上一章的钩子。

**章号有洞是正常的**，别当漏写去补。`query_tasks` 看那一段派给谁了。

## 第三类：公共文件不属任何人

这几个文件既不是你的地盘也不是别人的，却**每写一章、每改一条大纲就必然要碰一次**——可预测、高频，而且不算越界：

| 文件 | 谁会来加行 |
| --- | --- |
| `01-设定/05-术语与命名表.md` | 主笔新立了一个词；任何人发现跨文件不一致 |
| `01-设定/06-年表.md` | 本章确定了一个新的时间锚点 |
| `02-大纲/00-全书大纲.md`「伏笔收放时间表」 | 大纲改了某条伏笔的收放章号 |
| 各文件末尾的裁决记录与修订记录 | 任何人裁完一条 |

它们靠的不是地盘划分，是另一套做法：**先在通道里说一声、只加自己那一行、不动邻行。** 冲突真出现时也别自己合并——问那一行的作者。

术语表自己还多加了一条：**发现别的文件和它冲突，写进第九节冲突清单，不要自己去改别人的文件。**

### 「不碰」拦的是返工，不是拦你兑现已登记的挂账

派单里写「这几章你已交，不要回头改」，目的是**防止把交完的稿子反复推倒重来**。它不是要你保住一个已知的矛盾。

**分界线**：你回头动那一章，是因为**又想到一个更好的写法**（＝返工，不许），还是因为**当初交稿时就登记过的一个前提变了**（＝兑现挂账，该动）。

2026-08-30 真实发生过一次。通道 5 交 `0041` 时，元信息「待确认」里写死了一条挂账：「若通道 3 另有定法，本章第 3、5 段两处引文随之改，情节不受影响」。后来通道 3 定的接口确实和它假设的不一样，而派单方（我）当时已经说过「那个接口我已锁定」、并在下一单里把 `0041` 圈进了「不碰」。

**不动的后果是 `0040` 与 `0041` 在纸面上当场打架**：前一章他说要让一段石阶，后一章开篇写他说名额保不住。

**责任在派单方**：接口是我锁错的、被下游改对的，**而把改动往下游传是我的活，我漏了**。通道 5 补上了这一步，判得对。

**它做对的是三件事，缺一件都不成立**：① 只动自己那一章，上游 `0040` 一个字符没碰；② **立刻报，并且明说「这是我的解读，不是你的明文授权，你要是认为该等你点头，我下次先问」**；③ 把改动范围、字数变化、依据的那条挂账原文一并给出，让派单方能一眼判回不回滚。

**所以规矩是：遇到这种情况，做，然后立刻报，并主动把回滚的门留着。** 另外两条路都更差——**闷头做**是把派单方蒙在鼓里；**干等**是让两章矛盾着躺在树上，而下一个读它的人不知道该信哪一章。

## 盲覆盖：约定和报告都防不住它

「不动邻行」不只对公共文件成立，任何被两个会话先后各追加过一次的同一处都算。

它长这样：一个会话先在某条词条的说明里补了一句「2026-08-27 全组广播定为规矩」，另一个会话随后改同一行的标准写法，匹配串写得太短、跨过了那句备注，一次「成功」的替换把它吞掉。

**它不是并发编辑。** 两次写入先后发生，各自都合法，第二个人也确实在通道里说过。冲突提示不会出现——工具视角里根本没有冲突，它只是照给定的匹配串替换了一段，而那段里混着别人的字。

做法是把匹配串锚在**你自己写下的字**上，改完立刻重读那一段确认邻居还在。**没有任何机制在守这一条**，而且它出问题时不会有任何东西变红——门禁扫描查的是正文里的禁用词和字数，查不出一句备注被吞了。

**共享工作树上的盲覆盖仍然危险。** git 能恢复已提交版本，但不能替你判断未提交改动属于谁；一旦回退整份文件，还可能覆盖别人的工作。

## 有版本控制，但共享工作树仍要克制

仓库根已有 `.git`，提交由通道 1 收口。详见 [workflow.md 的取证](./workflow.md#取证这东西是谁什么时候改的)，这里只写它对多通道协作的三个直接后果：

**一，以整棵树为输入并写回的操作，在共享树上一律不得单方面跑。** 全库禁用词批量替换、批量重排章号、批量回填字数——它的输入包含别人写到一半的部分，而且回退时可能连带未提交改动。要跑先在通道里约定谁跑、什么时候跑，跑完人工过一遍。

**只读的扫描随时可以跑**，跑了也只影响你自己的终端。危险的是会写回文件的那一类。

**二，大范围改动之前先复制一份。**

```powershell
Copy-Item -Recurse '01-设定' "$env:TEMP\bak-01设定-$(Get-Date -f yyyyMMdd-HHmmss)"
```

改完确认没问题、并等本轮复核全部收口之后再删。备份保留未提交工作树的快照，Git 保存已提交版本，两者用途不同。

**三，修订记录是裁决原因账，写了才算数。** 别的通道可以用 `git diff` / `git log` 看改了什么，但只有文件末尾的修订记录能说明为什么这么改、哪些口径被同步。**改了内容不写修订记录，等于把那次裁决从长期上下文里抹掉了。**

## 报什么，不报什么

**只报对方从自己那一轮里看不到的事。** 四类：

- 你改了公共文件会拆到他：术语表新增禁用词、年表加了锚点、模拟刻度的口径变了
- 决策类事实：终裁的结论、章号区间的分配、被否掉的写法
- 他的稿子**读得通但事实不对**——这是旁观者唯一真能提供的，扫描拿不到
- 地盘与顺序协调

**别人正在写的章节里的错别字、排版一律不报。** 他自己的门禁扫描比消息快。报了只会驱使他去看一个正在变的地方。

**审校的例外**：审校报的就是别人稿子里的问题，那是他的本职，不受这条约束。但仍然要等对方 `report_task(status="done")` 之后再报——审一份还在动的稿子，结论出来就作废了。

**`broadcast` 留给终裁，不要拿来播报进度。** 裁决落地时记明日期、决定人和依据，按当前术语表「跨文件冲突清单」「裁决记录」的格式留痕。进度用 `report_task` 或 `send_progress`。

## 断言有保质期，但设计建议没有

**共享树上关于当前状态的任何断言都有保质期，文档不例外。** 「某文件某小节写着什么」「这个数没登记」「某章还没写」——这类结论型消息发出前重新取一次证据，成本比一轮仲裁低得多。

这也是[「报错之前必须打开源文件确认原文」](./domain.md#冲突按什么顺序裁)在多会话下的加强版：不只要打开，还要**在发消息之前那一刻**打开。

**但这条管不了关于「还不存在的东西」的建议。** 「这个单元的玩法和卷二单元 3 撞了」「这条伏笔解在卷五会让卷六断供」无法预先查新，因为它指向的是尚未写下的章节。两类并成一条，结论会滑到「什么都别建议」——而这恰恰是只读会话产出的全部价值。

### 反过来也会出事：证据太新，新到是对方刚写的

上一节防的是证据太旧。**还有一种相反的错，而且更难看出来：你重新取证了，取到的却是执行人这一刻的成果，你把它读成了「原本就是这样」。**

2026-08-30 在 v1 旧稿真实发生过一次。派单方让通道 2 改 `0015/0016` 的章名，单子里第 3 条是「连 `09-前36章逐章细纲.md` 第 15、16 行一起改」。**该旧细纲随 v2 重写已移除，这里只作历史案例，当前逐章准据见对应卷纲。** **派完单两分钟后**，派单方为了别的事打开那份细纲，看见第 15、16 行已经是两个像模像样的章名，于是得出结论「细纲一直是对的，漂的只是正文文件名」，并发了一条更正：**「细纲不要改，原单第 3 条作废。」**

那两行是通道 2 在这两分钟里写进去的。真实情况是**细纲与正文两边原本都写着「中高潮（上）/（下）」，同时错**。

- **它没有报错。** 派单方确实打开了源文件、确实看的是原文，取证动作一步没少。
- **它差点把一次正确的修改撤销掉**：通道 2 若还没动手而照办了，那两行就会被派单方亲手留在权威文档里。
- **更远的代价是那句假叙述**：「细纲一直是对的，只是正文文件名漂了」一旦写进记录，下一个人会据此推出「大纲侧不用查」，于是又一盏假绿灯。

**怎么防（按成本从低到高）：**

1. **派出去的活，在对方 `report_task` 之前不要拿目标文件当权威。** 你自己刚把它变成一个正在动的地方。
2. **一致就是可疑。** 你派了 A，随后发现现状已经是 A——**先假设是对方干的，不要假设是你派错了**。核一眼时间：任务 `createdAt` 与文件改动时刻一比就清楚。
3. **要推翻自己的派单，先问执行人，不要直接发更正。** 一句「你是不是已经动过第 15、16 行了」比一条更正便宜得多。
4. **执行人收到「与你手上的活相矛盾」的更正时，先答再改。** 本次是通道 2 顶了回来、附三条取证（审校文件里白纸黑字写着细纲也是错的、旧行带着「这是结构标签」的加粗记号、两个名字一个自拟一个照抄审校备选所以只可能是它刚写的），这件事才没有滑过去。**这条比上面三条都值钱：派单方错了没有任何机制会报，只有执行人在现场。**

## 只读会话要派具体任务，否则是负收益

只读会话最有价值的产出是**没人有空去查的横向账**：某个数在全书用过几次分别什么量纲、某条设定被哪些章引用过、某个玩法在哪几卷重合。

这类账人记不住，需要有明确范围的人去查。v1 的 `0018` 曾有一句漏掉的现代词，专门扫词表后才现形；旧正文与旧词表节号已经作废，当前用术语表「7.3 现代词换法」和工作流的 v2 反验。

好任务的形状：**只读、边界清晰、结论能直接改变写入方的下一步。** 典型是：

- 把当前 v2 卷纲里的模拟刻度列出来，对机制「入世」「魂载」与已裁细则；未回填或待定项单列，只报原文与准据
- 从已写正文里逐章列出陈九的连续对话，与人物「说话」小节核对语气
- 把正文出现「三年」的地方连原句列出来，分清入宗前情、现实历时与模拟历时，再对年表与卷纲

派任务时写明**不要做什么**——不改文件、不替别人重写、不下设定裁定。否则调研会变成第二份实现。

## 决定权

**要么归 owner，要么被人明确授权。** 涉及设定或情节走向的一律不自己拍板：写进[术语表第九节冲突清单](../01-设定/05-术语与命名表.md)，`send_to_session` 通知责任通道。能直接改的错字、写法、与真源对不上的数字才自己改并记录，判据见 [triage-labels.md](./triage-labels.md#谁能自己改)。

被授权替别人拍板时，**把自己的能力边界写在裁决里**：读过哪些文件、没读哪些、因此裁的是方向还是具体条目。定方向与约束强度就够了，具体怎么改留给 owner——他知道那一卷里的伏笔，裁决方不知道。

## 不写进本文的

**哪个窗口干什么**每次现分，不写下来。已有文档里出现的「通道 2 已改 `06-年表.md`」这类记录是当时那一轮的留痕，不是长期归属。本文只留换一批会话仍然成立的部分。
