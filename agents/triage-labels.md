# 问题分级

审校记录里的严重度、归属和状态各是一套词。混着用会让「这条到底要不要现在改」变成每次重新讨论一遍的事。

## 严重度

`04-审校/README.md` 第二节定的就是这三级，审校报告按它分节。

| 级别 | 判据 | 主笔怎么处理 |
| --- | --- | --- |
| **必改** | 违反设定、违反模拟器规则、没完成大纲那件事、伏笔埋收错位、章末无钩子、字数出界、出现了不该出现的词 | 当轮必须改完，改完回审 |
| **建议** | 能读但不够好：爽点弱、对话干、钩子平、标题偏气氛 | 可以不改，但要在回执里写一句为什么 |
| **可忽略** | 个人口味，以及**专门查过、确认没问题的地方** | 记录即可，不用回 |

**「可忽略」这一节不许省，它装的不只是口味问题。** 你专门交叉比对过、确认对得上的点要写进去，下一轮审校才能据此跳过。理由见 [issue-tracker.md](./issue-tracker.md#可忽略那一节不要省)。

**必改的门槛比直觉低。** 这本书目前只有二十几章、设定文档全部封存定稿，所以「与设定对不上」几乎一律是必改——现在改一句话，比写到卷三再回来改三十章便宜得多。判据不是「读者会不会发现」，是**「按这条写下去，后面还成不成立」**。

**门禁扫描报出来的一律是必改。** 它查的每一项都是纯字面的硬指标，没有讨论空间。**具体查哪些以 [workflow.md 的门禁](./workflow.md#门禁) 为准，这里不复制清单**——那份会随着新检查加进去而变，抄一份在这儿只会变成两套口径。

## 归属：这条该改哪边

每条问题除了严重度，还要判一个「改哪边」。**默认顺序是硬的，而且和长篇后期的通行做法相反：**

```
模拟器机制 → 其余设定 → 大纲 → 正文
```

**箭头指向让步方向：正文让给大纲，大纲让给设定，设定让给机制文档。** 理由与它的保质期（正文体量上来之后要重新议）见 [domain.md](./domain.md#冲突按什么顺序裁)。

| 归属 | 什么时候是它 |
| --- | --- |
| `正文` | 正文与任何上游文档对不上，或正文自相矛盾 |
| `大纲` | 卷纲 / 细纲声称的事实，与设定或全书大纲对不上 |
| `设定` | 世界观 / 人物 / 年表与模拟器机制对不上 |
| `术语表` | 只是写法不一致，内容没错 |
| `待裁` | 涉及情节走向或跨了两卷，审校不该自己拍板 |

`待裁` 的一律写进[术语表第九节冲突清单](../01-设定/05-术语与命名表.md)并 `send_to_session` 通知责任通道，不要自己改完了事。

## 谁能自己改

| 能自己改 | 必须先报 |
| --- | --- |
| 错字、标点、半角混入 | 任何设定级改动 |
| 与真源对不上的数字、年份、称呼 | 情节因果与人物动机的调整 |
| 禁用词换成术语表里的标准写法 | 已封存定稿条目的修改 |
| 元信息字段回填（字数、伏笔、状态） | 章号区间、分卷比例 |

分界线是**这条改动会不会让别人手上的东西作废**。把「概念」改成「说法」不会；把赵堂的年龄从 47 改成 52 会——年表、世界观、人物档案三处都得跟着动。

**但审校不在这张表里。** 审校**一个字都不动 `03-正文/`**，哪怕是错字。它只写 `04-审校/` 下的文件，定位到句、给建议改法，由主笔决定。三条理由在 `04-审校/README.md` 第四节：语感是一个人的、会撞车、审校可能是错的。

## 定位格式

`章号 / 第 N 段 / 原句前 8–10 字`。三样缺一不可——只写章号，主笔找不到；只写句子，重复句会歧义。段号从正文第一段算起，**元信息头不计**。

```
| 0003 / 第 8 段 / "他又死了一次" | 一 | 当天第 4 次死亡，超配额 | 02-模拟器机制.md 第 4 条 | 删一次，或改成活满时长自然结束 |
```

**不用行号。** 正文是会被改的，行号活不过一轮修改；段号加原句在改动之后仍然找得到，找不到本身就是信号——说明那句话已经被改过了，这一条要重新看。同理，跨文件引用引小节名不引行号，这是 2026-08-27 全库执行过的一次清理。

**依据那一列要指到具体条款**，比如「`02-模拟器机制.md` 第 4 条」「术语表 8.4」，不要只写文件名。

## idp-mcp 任务状态

`report_task` 只有三个状态，另有两个由系统维护。

| 状态 | 你该做什么 |
| --- | --- |
| 收到任务 | 立刻 `report_task(status="working")` 认下来，别沉默 |
| 开工中 | 换一个阶段报一次 `working`，`result` 里写做到哪了 |
| 完成 | `report_task(status="done")`，`result` 列章号、实计字数、`待确认` 有没有 |
| 干不完 | `report_task(status="failed")`，`result` 里写清已经做到哪、卡在什么地方 |
| `blocked` | 目标通道被 `set_channel_lock` 锁住时系统置的，不是你报的 |

**`result` 写「写完了」等于没报。** 下一个人接手时拿不到任何东西，只能自己重读一遍你写的东西。

## 门禁具体不查什么

[workflow.md 那段扫描](./workflow.md#门禁)只查纯字面的东西——**查哪几样以那一节为准，本页不列清单**（列过两次，两次都忘了跟着更新）。下面这些每一条都能在扫描全绿的树上存在，**报「扫描通过」时要知道自己没证明什么**。

| 盲区 | 为什么漏 |
| --- | --- |
| **模拟的次数、时长、伤痕对不对** | 要跨章累计当日死亡数、要对本卷的模拟刻度档位。这是本书最致命的一类错，机器完全查不了 |
| **信息边界被破** | 云昭「知道」某件事这个前提，只存在于前面章节的情节里。`04-人物.md` 那处「模拟里看见赵堂年轻时」就是这么漏过去的 |
| 同一个毛病换一种措辞 | 禁用词是纯字面 `Contains`，不是语义匹配。「成功率八成」被抓，「八成能成」不被抓——后者本来就合规，真正的漏网是那种绕开字面、味道却跑掉的句子 |
| 提前泄底 | 扫描只认死了「仙盟」「魔门」两个词、只管前 30 章。各卷卷纲单列的「本卷不许说破」（如卷三老周那件事）机器一概不知道哪些字算说破 |
| 相对时间说法 | 查的是登记过的数值，「上个月」「去年」「这三年」不含数字。而本书三年 / 二十年 / 四十一年 / 三百年四条时间线交织 |
| 章末有没有钩子 | 机器分不出「抛问题 / 点代价 / 推一步」和一句没信息量的气氛句 |
| 一章讲了几件事 | —— |
| 语域用错 | 「模拟器」三个字扫得出来，但「他退出了这一局」全是合法字符 |

两条推论：

**加一条禁用词之前先确认它真的会命中，也确认它不会误伤。** 这条已经踩过：初版扫描没有跳过元信息头，结果每一章的 `状态: 待审校` 都命中禁用词「状态」，26 章报了 26 条假阳性——**一行给假安心或者给满屏噪声的规则，比没有那一行更危险**，前者让人以为守住了，后者让人开始无视报告。

**看到报错的位置不在自己地盘，先想想同一个毛病在自己地盘里有没有。** 扫描报的是句子，你要修的是毛病。
