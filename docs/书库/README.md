# 玄幻书库 · 100 本

一份可离线检索的玄幻小说**元数据档案**，快照日期 **2026-08-26**。

---

## 0. 合规声明（先读这一条）

**本库只存公开元数据、官方书页链接与封面图，不存任何作品正文。**

这 100 本全部是商业平台在售/在营的版权作品。本项目中「下载」的定义是：把每本书在平台上**公开展示的元数据**、**官方书页链接**、**封面图**落到本地，成为可离线检索的目录，而不是把小说内容存下来。

- `简介摘要` 一列是各通道**用自己的话概括的 60 字以内摘要**，不是平台简介原文的复制。
- 归档脚本 `.scrape/archive.mjs` 中**没有任何拉取章节或目录正文的代码**，这是硬性约束。
- 抓取全程只走平台官方书页、官方榜单页与平台开放接口，不访问盗版站。

**要看书请走各平台正版**，本库每一行的 `官方书页URL` 都可直接跳转。

## 2. 怎么用

**翻阅**：直接用浏览器打开 `书库归档/index.html`。封面墙 + 关键词搜索 + 按平台/分类/核验状态筛选，点书名跳官方书页。单文件、无需联网、不依赖服务器。

**重新生成**：

```bash
node .scrape/merge_qc.mjs              # 校验三份分表并合并出总表 + 质检报告
node .scrape/merge_qc.mjs --no-merge   # 只出报告，不覆盖总表（自检时用这个）
node .scrape/archive.mjs               # 从总表生成封面/JSON/manifest/索引页
node .scrape/archive.mjs --no-covers   # 不下封面，只重建索引
```

归档器**可重入**：已存在的封面不会重下，单张失败不影响整跑，请求间隔不低于 1 秒。

**自测**：`node .scrape/archive_selftest.mjs`（32 项）、`node .scrape/merge_selftest.mjs`（32 项）。两套都起本地服务器真跑，不打扰线上站点。

### 两个容易踩的约定

1. **`是否核心玄幻盘` 是三值不是布尔值。** 下游若按布尔值筛选会漏掉 `待定` 那类。

   全表目前只有 `#42`《廓晋》一条 `待定`：平台把它归入「历史·两晋隋唐」，与玄幻明显不符，但当时**只有平台分类这一个信号**，不足以判否，故悬置。
   对照 `#49`《山河鉴》——平台分类是「游戏·游戏异界」，内容标签是「策略流/三国/考据」，**两个独立信号同向**，判据充足，直接判 `否` 而不悬置。

2. **空值就是空的，没有占位符。** 取不到一律留空，不填 `N/A`、`未知`、`-`、`0`。空值可统计，占位符不可。

### 5.1 番茄 11 行缺 ID / URL / 封面 —— 是同一个问题

## 6. 跨站同书：不去重，也不拆合

同一本书在两个平台各有书页时，本表的处理规则只有一条：**序号是主键，底本给一个序号就占一行，给两个序号就占两行。**

**甲类 · 底本占两个序号 → 两行都保留并互指**

- 《盗梦千年》：`#67` 七猫（34.9 万） + `#94` 纵横（38.0 万）

两行字数不同是正常的，**同一本书在不同平台的连载进度本就不一致**，不是数据矛盾。

**乙类 · 底本只占一个序号 → 保留一行，另一站 ID 记在核验状态里**

`#26` 从变身少女开始斩妖除魔、`#60` 太荒吞天诀、`#78` 长夜君主、`#85` 苟在武道世界成圣、`#90` 巫师：从合成宝石开始。

> **下游注意：甲类不要合并成一行，乙类不要拆成两行。** 两个方向都会破坏 1–100 的主键完整性。

## 7. 采集方法与踩过的坑

### 7.1 最值得记住的一条：不报错不等于成功

本轮遇到三个同型陷阱，**接口都返回成功、都不抛异常、都没给数据**：

| 现象 | 表面 | 实际 |
| --- | --- | --- |
| `categoryV2` 是 JSON 字符串 | 代码不崩、日志显示 ok | `Array.isArray(x) ? x : []` 对 100% 的书返回空数组，`平台分类` 整列被静默清空 |
| 封面 CDN 收到不存在的 bookId | 200 + `image/jpeg` | 返回 6909 字节的占位图 |
| 番茄软限流 | 200 + 正常 content-type | body 为空 |
| 起点搜索抽取器写死 `/book/{id}/` | 200 + 95KB 非空 body | 实际链接是 `/chapter/{id}/0/`，任何查询都返回 0 结果（详见 7.5） |
| 核验状态分隔符写成全角 | 质检「通过」 | 校验器用 `startsWith` 判前缀，`已核实（作者）-…` 被静默接受成新状态值 |

**改完必须回看目标字段有没有真的取到值，不要只看退出码。**

最后一例的教训略有不同：**校验通过也不等于数据合规**。预期外的输入若没有被明确拒绝，就会被静默接受成另一种东西。前缀判断已改为白名单精确匹配——必须是三个前缀之一，其后要么结束、要么紧跟半角 `-`。

### 7.2 封面校验：两层防护，各管一类

- **sha256 查重**：多本书拿到同一张图 → 判为占位图。管的是**批量**占位。
- **体积下限**：小于阈值 → 判为占位图或拦截页。管的是**单发**占位——全表只有一本中招时哈希没有第二张可比，此时体积下限是唯一岗哨。

两层不是主次关系，是各管一类。**因此体积下限不得低于已知占位图体积（6909 字节）**，这条已写成 `KNOWN_PLACEHOLDER_BYTES` 常量加启动断言：任何平台阈值降到这条线以下，归档器直接启动失败。

阈值按平台分档，**两类值的可信度不同**：

| 平台 | 阈值 | 真封面最小 | 可信度 |
| --- | --- | --- | --- |
| 起点 / QQ阅读 | 15000 | 21710 | **有反例支撑** —— 确实拦得住那张 6909 的占位图 |
| 番茄 | 8000 | 11488 | 仅启发式 —— 未观测到该 CDN 的占位图 |
| 七猫 / 纵横 | 15000 | 28708 | 仅启发式 —— 同上 |
| 未知平台 | 10240 | — | 兜底 |

**单平台实测得出的阈值不能直接当全局阈值。** 起点侧封面中位数 81KB，番茄最小的只有 11KB；曾有人依据起点数据建议把下限抬到 20000，那会静默误杀一半番茄封面。

（体积分布由两个通道用不同脚本、不同数据源独立测出且逐个吻合，可放心引用。）

### 7.3 番茄封面签名链 → 永久链

番茄书页 `thumbUrl` 是带 `x-expires` / `x-signature` 的签名链，约 24 小时失效，过期后返回 403 + `text/html`。

**等效永久形式**：主机名归一到 `p6-novel.byteimg.com`，丢掉整个 query。

```
签名链  https://p6-novel-sign.byteimg.com/novel-pic/<hash>~tplv-resize:225:300.image?lk3s=…&x-expires=…&x-signature=…
永久链  https://p6-novel.byteimg.com/novel-pic/<hash>~tplv-resize:225:300.image
```

两者 sha256 逐条完全一致（18/18 实测），是同一字节流。两个坑：

1. **不能只把 `-novel-sign.` 改成 `-novel.`** —— `p9-novel` 没有免签名对应，固定返回 403。必须**全部归一到 p6**。
2. 路径尾部的 `~tplv-resize:225:300` 是尺寸参数，**要保留**，不是脏参数。

归档器已内建这个归一化，所以即使 CSV 里存的是签名链、且签名已过期，重跑依然能下到图。

### 7.4 其他平台细节

- **QQ阅读封面路径要去前导零**：目录段取 shortId 后三位的**数值**而非字符串截取。`33530052` 的后三位是 `052`，但正确路径是 `/cover/52/`，用 `052` 一律 404。只在十分之一的概率下暴露。
- **番茄 PUA 字形混淆分两层**：榜单页 `/rank/…` 的 `book_list` 里书名作者被私有字体污染（353/360），但书页 `/page/{id}` 的 `__INITIAL_STATE__.page` **返回干净字符串**（0/360 污染）。换取数位置即可绕过，不必标 `待核实-PUA`。
  PUA 替换是**单字符等长替换**，因此可用「同长度 + 所有非 PUA 位逐位相等」做骨架校验，再用书页干净名复核——全程不猜字。
- **番茄限流是 IP 级的**：换通道跑绕不过去。多通道并行不仅无法规避，反而更快撞线。**下次快照需要全局排队，不要并行抓同一站。**

### 7.5 「搜不到」必须配正对照才算数

本轮出过一次**把存在的书判成不存在**：`#49`《山河鉴》曾被写入「检索未命中」，实际它好好地挂在起点上（`1046770618`，余弦公式）。

根因是抽取器写死了 `/book/{bookId}/` 这个链接形式，而起点搜索结果给的是 `/chapter/{bookId}/0/`。于是**任何查询都返回 0 结果**——接口 200、body 95KB 非空、不报错，看起来就像「这本书不存在」。这是 7.1 那类陷阱的第四个变种，只不过这次坏掉的是自家抽取器而非平台接口。

发现它的办法是**正对照**：拿一本确定存在的书（《异度旅社》）跑同一个查询，它也返回 0 结果——对照不亮，说明坏的是方法而不是数据。

> **规则：「搜不到」是一个结论，不是一次失败。** 写下缺席之前，必须在同一批次跑一个已知存在的正对照；对照不亮就不允许写缺席。
