# 玄幻书库 · 统一字段规范（v1）

- **制定**：通道 1（总协调），2026-08-26
- **适用**：通道 2 / 3 / 4 产出的分平台档案 CSV，以及通道 5 的合并总表
- **底本**：`docs/玄幻选题库-100本-20260826.csv`（100 条，序号 1–100 不变，作为主键）

---

## 0. 合规红线（所有通道必须遵守）

1. **不下载、不抄录任何作品正文**。这 100 本全部是商业平台在售/在营的版权作品，抓正文即侵权。
2. **不访问盗版站**。只走平台官方书页、官方榜单页、平台开放接口。
3. 「下载」在本项目中的定义是：**把每本书的公开元数据、官方书页链接、封面图落到本地成为可离线检索的档案**，不是把小说内容存下来。
4. 官方简介（平台书页上公开展示的营销文案）**只摘不抄**：用自己的话压到 60 字以内写进 `简介摘要`，不要整段复制。
5. 抓取节流：单站请求间隔 ≥ 1 秒，遇 403/429 退避 60 秒再续，不要原地重试风暴。

## 1. CSV 列定义（顺序固定，20 列）

| # | 列名 | 必填 | 说明 |
| --- | --- | --- | --- |
| 1 | `序号` | 是 | 沿用选题库 1–100，**不得重排、不得新增** |
| 2 | `书名` | 是 | 以平台官方书页为准。番茄网页端有私有字体混淆，PUA 字符需标记，见第 3 节 |
| 3 | `作者` | 是 | 底本缺失的必须补齐 |
| 4 | `平台` | 是 | 起点 / 番茄 / 七猫 / 纵横 / QQ阅读，五选一 |
| 5 | `书籍ID` | 是 | 平台内部 ID（番茄为 19 位数字，起点为 bookId，余同） |
| 6 | `官方书页URL` | 是 | 可直接打开的完整 URL |
| 7 | `字数(万)` | 是 | 保留一位小数。**注明口径**：见第 2 节 |
| 8 | `连载状态` | 是 | 连载中 / 已完结 |
| 9 | `平台分类` | 是 | 平台自身的分类字段原文，**不要替换成你认为对的分类** |
| 10 | `内容标签` | 否 | 平台书页上的标签，`/` 分隔 |
| 11 | `总章节数` | 否 | 整数 |
| 12 | `首发时间` | 否 | `YYYY-MM-DD`，取不到留空 |
| 13 | `最近更新` | 否 | `YYYY-MM-DD` |
| 14 | `榜位快照20260826` | 是 | 沿用底本原值；若本轮实测有变，写新值并在 `核验状态` 标注 |
| 15 | `核心设定` | 是 | 默认沿用底本；底本为空的补一句。**例外：若底本这句与官方书页的实际内容相矛盾（通常发生在书名订正之后——底本原本描述的是一本认错了的书），必须按书页改写**，并把底本原句留在 `数据来源` 里以便追溯。沿用底本的前提是底本指对了书，这个前提不成立时就不能沿用 |
| 16 | `简介摘要` | 是 | **自己概括，≤60 字**，不许整段复制官方简介 |
| 17 | `封面URL` | 否 | 图片直链 |
| 18 | `是否核心玄幻盘` | 是 | `是` / `否` / `待定`，沿用底本。`待定` 用于平台分类与题材明显不一致、需补内容标签后再判的条目（如 #42《廓晋》平台归历史·两晋隋唐）。**理由见第 5 节第 5 条** |
| 19 | `数据来源` | 是 | 如 `番茄官方书页 2026-08-26` |
| 20 | `核验状态` | 是 | **前缀**必须是 `已核实` / `待核实` / `冲突` 之一；前缀后可紧跟 `-` 加一句简短说明（如 `已核实-字数取书页当前值，起点图首V时为18万`、`待核实-PUA`、`冲突-两个作者名待定`）。**校验只匹配前缀，不校后缀**。较长的证据链写 `数据来源`，不要塞进本列 |

### 空值约定

取不到就**留空**，不要填 `N/A`、`未知`、`-`、`0`。留空是可统计的，占位符不是。

## 2. 字数口径必须统一

底本混了三种口径，这一轮要收敛：

- 起点：起点图记录的是**首 V 时刻**字数，QQ阅读书页显示**当前**字数，两者能差 3 倍（《武道！》18 万 vs 51.3 万）。
- **本轮一律取「抓取当日平台书页显示的当前字数」**，即 2026-08-26 快照。
- 若你保留了首 V 字数这类另一口径的值，写进 `核验状态` 备注，不要塞进 `字数(万)`。

## 3. 番茄私有字体混淆：分两层，只有一层需要处理

番茄用私有字体对文字做字形混淆，被替换的字符落在 Unicode PUA 区（`U+E000`–`U+F8FF`）。**但混淆只作用在榜单页，不作用在书籍详情页**——这一条经通道 3 与通道 1 两路独立验证：

| 数据来源 | 是否混淆 | 实测 |
| --- | --- | --- |
| 榜单页 `/rank/…` 的 `book_list` | **是** | 353 / 360 本的书名含 PUA（98%） |
| 书籍详情页 `/page/{id}` 的 `window.__INITIAL_STATE__.page` | **否** | 360 本全部干净，0 含 PUA |

同一本书在两处的差别（PUA 字符在终端直接不显示，所以看起来像「掉了字」）：

| 榜单接口返回 | 书页真名 |
| --- | --- |
| 退休勇买魔王仆 | 退休勇者买下魔王当女仆 |
| 怪图鉴：哥布林血脉始 | 怪物图鉴：从哥布林血脉开始 |
| 领巫：限魔晶始求！ | 领主巫师：从无限魔晶开始求学！ |

### 操作规则

1. **一切文字字段以书页为准，不要从榜单页取书名或作者名。** 只要 ID 落在书页上取数，就不会有 PUA，也**不需要**标 `待核实-PUA`。
2. **不要拿底本书名去榜单数据里反查 ID**，98% 的名字是坏的，这条路走不通。已验证可行的替代是：把已知 bookId 全量跑详情页拿干净书名，再回头匹配。
3. **不要猜字、不要用相似字替换。** 若必须从榜单侧做候选筛选，可利用「PUA 只替换单个字符、长度不变」这一点做骨架校验（同长度 + 所有非 PUA 位逐位相等才算候选），但**候选必须再拿书页复核才能定稿**。
4. 检测函数用**不带 `g` 标志**的正则：`/[\uE000-\uF8FF]/.test(s)`。带 `g` 时 `test()` 会在调用间推进 `lastIndex`，连续判定给出错误结果（本项目已因此误报过一次比例）。

## 5. 已知的坑（前几轮踩过，别重踩）

1. `.scrape/scrape_books.mjs:46` —— `(p.categoryV2 || []).map` 会抛 `map is not a function`，上一轮 120 本全灭（`books_run.log` 只有一行 `ok=0`）。

   **根因不是「非数组对象」，是 `categoryV2` 本身就是一个 JSON 字符串**（形如 `"[{\"ObjectId\":258,\"Name\":\"传统玄幻\"}]"`）。这个区别决定修法对不对：

   | 写法 | 结果 |
   | --- | --- |
   | `(p.categoryV2 \|\| []).map(...)` | 抛错，整跑失败 |
   | `Array.isArray(p.categoryV2) ? p.categoryV2 : []` | **不崩，但对 100% 的书返回空数组**——`平台分类`（必填）与`内容标签`两列被静默清空且不报错，比崩掉更难发现 |
   | `asArray(p.categoryV2)`（先 `JSON.parse` 再判数组，解析失败返回 `[]`） | **正确**，已落在 `.scrape/lib.mjs` |

   > 教训：**「不再抛错」不等于「修好了」。** 改完必须回看目标字段有没有真的取到值，不要只看退出码。同类隐患 `chapterListWithVolume`（实测是真数组）也已统一走 `asArray`。
2. 选题库第 84 条《苟在初圣魔门当人材》作者存疑：库内记「三行的书哟」，移动端月票榜抓到「鹤守月满池」，而后者是《让仙门再次伟大》作者，疑为字段错位。**通道 2 本轮必须在起点书页二次核对。**
3. 选题库第 49 条《山河鉴》已标【已失效 20260826】，第 47 条《急急如律令》平台分类是**科幻·进化变异**不是东方玄幻。这两条的修订已完成，抄档案时照修订后的抄。
4. QQ阅读榜单页不给首发日期，只能确认「上架 30 天内」，`首发时间` 该留空就留空。

5. **底本的身份字段（书名 / 作者）有约 10% 不可靠，必须逐条回平台核，不要当前提。** 本轮已查实 10 条：

   | 序号 | 底本记录 | 平台实际 | 错型 |
   | --- | --- | --- | --- |
   | 46 | 作者 大眼珠子 | 远瞳（`大眼珠子` 是读者昵称，同一人） | 别名误当二人 |
   | 50 | 《武圣》月票 50–60 位·万订 | 九灯和善作品中无此书，两个候选均不符 | 书名不可靠 |
   | 52 | 《一龙之力》/ 天王哥 | 《以一龙之力打倒整个世界！》/ 唐宋元明氢 | 书名缩写 + 错作者 |
   | 66 | 《我怎么成掌门孩子他爹了》 | 《我一杂役，怎么成掌门孩子他爹了？》 | 书名缩写 |
   | 67 | 《盗梦长生》 | 《盗梦千年》 | 书名讹写 |
   | 69 | 作者 妖妖妖 | 梁山老鬼 | 错作者 |
   | 71 | 《女大三千万》 | 《混沌塔》 | 旧名/宣传语 |
   | 83 | 作者 烟雨江南 | 懒鸟 | 错作者 |
   | 84 | 作者 三行的书哟 | 鹤守月满池 | 错作者 |
   | 91 | 书名 日落红尘 | 《齐天》，日落红尘是作者 | 字段错位 |

   **判别与核验方法**：

   - **作者页是最强的归属证据**。平台的作家主页会列出该作者全部在架作品；书在不在这个列表里，一查即知。第 46、50、52 条都是这样定的。
   - **「同一作者写了两本书」与「字段错位」要分清**。第 84 条初判为抓取字段错位，实际是该作者同时有两本书在架，我们把它读成了串行——前者要修工具，后者要修读法。
   - **别名不等于两个人**。第 46 条我方一度断定「远瞳与大眼珠子是两位不同作者」并要求撤回别名假设，核实后证明错的是这个断定：`大眼珠子` 是读者给远瞳起的昵称。**凡涉及人物同一性，一律以平台作者页为准，不得凭印象断言。**
   - **凡拿「搜不到 / 未命中 / 不存在」当结论的，必须同步跑一个已知存在的正对照。** 对照不亮，就不允许写缺席——那说明问题在你的抽取方式，不在那本书。#49《山河鉴》一度被判「站内检索未命中」，实因起点搜索页结果链接是 `/chapter/{bookId}/0/` 而非 `/book/{bookId}/`，按后者抽取则**任何查询都返回 0 结果**；拿确定存在的《异度旅社》做对照后立刻暴露。该书实际一直在（bookId 1046770618）。

     > 这类错比接口返回坏数据更危险：接口的错还能靠换源发现，**抽取方式的错会在每一次查询里稳定地给出同一个错答案，看起来很像一个可重复的事实**。

   - **榜单要按「整行」评估可靠性，不要按条目**。`docs/全网玄幻榜单调研-20260826.md:170` 那一行是把 QQ阅读首页多个不同模块（热门、最近更新、完本好书）的书混押成了一份「热门榜」，它根本不是一份榜单。第 83、84、86、50 四条错误全部出自这一行。**该行整段作废，下游不得再引用。**
