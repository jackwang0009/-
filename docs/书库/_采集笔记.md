## 0. 合规前提（不随平台变化）

只取书目元数据（书名/作者/分类/字数/状态/章节数/封面链接），**不抓正文、不访问盗版站**。简介一律自己重写，不复制官方营销文案。单站请求间隔 ≥ 1 秒，遇 403/429 退避 60 秒。

注意：抓书页时返回的 HTML 里**经常夹带第一章正文**（起点移动端尤其明显，单页可达 600 KB）。这些内容不要落盘、不要转述，只从中提取元数据行。

## 1. 起点

### 1.1 桌面站有反爬，必须走移动端

`www.qidian.com/book/{bookId}/` 与 `www.qidian.com/so/{关键词}.html` 一律返回 **`Safety check`** 拦截页，没有可用内容。

**改用 `https://m.qidian.com/book/{bookId}/`**，可正常返回。页面文本结构稳定，元数据集中在开头几行：

```
书名
作者名
分类·子分类          ← 例：仙侠·修真文明
连载 | 更新时间 2026-08-25 20:27:32   ← 或「完本 | ...」
No.6                 ← 月票榜徽章（有则出现，无则整块缺失）
男生月票榜
618.23万字
总字数
```

- 「连载 / 完本」是平台原词，写入 CSV 时映射成 `连载中 / 已完结`。
- 分类行是 `一级·二级`，**照抄，不要改成自己认为对的题材**。

### 1.2 移动端书页有约三成概率只返回阅读页

同一个 URL 多次抓取，结果不稳定：有时返回上面的元数据版块，有时**只返回第一章正文**（《青山》连抓三次全是正文，最终没拿到官方字数）。

应对顺序：① 原样重试一次；② 去掉/加上结尾斜杠再试；③ 换 QQ阅读同集团页面取值并在 `数据来源` 注明；④ 仍不行就留空。

### 1.3 作者页可用来做归属核验

`https://m.qidian.com/author/{authorId}/` 列出该作者全部作品与「火热连载」，是**核对署名争议最直接的官方证据**，比搜索引擎摘要可靠得多。

本轮两次用它定案：
- 《异度旅社》出现在远瞳作者页（`/author/4362948/`）的火热连载位 → 归属确认。
- 九灯和善作者页（`/author/3692225/`）11 本作品中**没有**《武圣》，其在连载作品是《这个武圣太谨慎了》→ 选题库该行书名存疑。

## 2. QQ阅读

### 2.1 两个端点分工不同，都要抓

| 端点 | 给什么 |
| --- | --- |
| `https://book.qq.com/book-detail/{shortId}` | 作者、更新时间、最新章节名、章节数、官方简介 |
| `https://m.novel.qq.com/detail/10{shortId}` | **分类 + 总字数**，格式如 `玄幻/东方玄幻· 516万字` |

`m.novel` 的 ID = `10` + `book.qq.com` 的 shortId。**这条规律要逐本验证**，拼出来打不开或书名对不上就改用搜索找正确 ID。

### 2.2 同一本书有大量官方镜像域名，内容一致但缓存新鲜度差很多

见过的官方镜像：`m.novel.qq.com`、`book.novel.qq.com`、`read.novel.qq.com`、`mwbook.read.qq.com`、`mreader.book.qq.com`、`mikan.book.qq.com`、`shuku.read.qq.com`、`ubook.reader.qq.com`、`aikan.qq.com`、`m.cover.qq.com`、`yuedu.book.qq.com`、`books.book.qq.com`、`m.appbook.qq.com`。

它们都是腾讯自有站，可以用，但**同一本书在不同镜像上的字数能差几个月的量**：

- 《我在永夜打造庇护所》：`ubook` 记 134 万（2026-03 快照），实际 239 万。
- 《大乾武圣！》：一个镜像 384 万，`book.qq.com` 430 万，官方分类页 489 万。
- 《太虚至尊》：`m.novel` 516 万（2026-05），官方分类页 528 万。

**取值规则：比对各页的「更新时间」，取最新的那个，并把另一口径写进 `核验状态`。**

### 2.3 分类列表页是本轮性价比最高的数据源

`https://book.qq.com/book-cate/20001-0-0-0-0-0-0-1`（20001 = 玄幻）

一次返回 20 本，每本带 `作者·分类·状态·字数`，而且是**同一时点的同口径快照**，比逐本抓镜像页准得多。本轮靠它一次性刷新了 8 本的字数（33/39/40/80/82/84/85/87）。

**注意**：该页的「最新章节 + 日期」明显错乱（《诡秘之主》显示 2018-04-01，《青山》显示 2024-05-25），**只用字数/分类/状态，不要用它的日期**。

`https://m.novel.qq.com/` 首页另有多个 TOP5 榜单模块与「完本好书 / 最近更新 / 最新上架」区块，适合做榜位交叉验证。

## 3. 第三方源的可信度分级

| 源 | 可信度 | 用法 |
| --- | --- | --- |
| 平台官方书页 / 官方分类页 / 官方作者页 | 高 | 首选，直接写入 |
| 阅文官方镜像（`bookresource.qq.com`、`kehuan`、`xszc` 等） | 中 | **缓存明显偏旧**，《这个地下城长蘑菇了》镜像 158 万 vs 实际 199 万；只在官方页取不到时用，且必须标注 |
| 起点图 `qidiantu.com` | 中 | 有每日字数流水，适合补官方页取不到的字数；但它记的部分是**首 V 时刻**口径，别和当前字数混用 |
| `booklink.me` 字数曲线 | 中 | 能给出精确总字数与起止日期，适合判断完结日 |
| 百科类（百度/搜狗/QQ阅读百科） | 低—中 | 只用于交叉印证作者与完结事实，数字不采信 |
| 盗版/聚合站 | 禁用 | 不访问 |

## 4. 封面 URL：模板推导 + 实测校验

模板推导本身不算事实，**必须实测到 HTTP 200 且 `Content-Type` 为 `image/*` 才可写入**，`数据来源` 标「模板推导+实测校验」。

- 起点：`https://bookcover.yuewen.com/qdbimg/349573/{bookId}/600.webp`
- QQ阅读：`https://wfqqreader-1252317822.image.myqcloud.com/cover/{段}/{shortId}/t7_{shortId}.webp`

**QQ阅读那个目录段要去前导零**：它是 shortId 的后三位**按数字取值**，不是纯字符串截取。`33530052` 的后三位是 `052`，但正确路径是 `/cover/52/`，用 `052` 会 404。本轮 #77《神道丹帝》最初判成「老书 ID 映射规律不同」，其实只是这一条踩空了。

**警告：200 不等于命中。** `bookcover.yuewen.com` 对不存在的 bookId 会返回 **200 + `image/jpeg` + 约 6.9 KB 的占位图**，而真实封面是 `image/webp`、30–215 KB。所以判定条件要三条齐全：状态码 200、`Content-Type` 为 image、**且体积明显大于占位图**。只看状态码会把假成功当真。

本轮 34 个候选实测通过 33 个。**一并记录 `Content-Length`**：若多条返回同一尺寸，多半是占位图而非真封面（本轮 33 条尺寸各不相同，均为真图）。

**副作用很有用**：封面探测可以当作 **bookId 的低成本校验**。《天命之上》的 bookId `1039831421` 只有第三方来源，封面实测 200 后即可采信；《神道丹帝》按 `1033530052 → 33530052` 推出的 shortId 探测 404，说明老书的 ID 映射规律不同，该条封面留空。

PowerShell 批量探测（注意逐条 sleep）：

```powershell
$r = Invoke-WebRequest $url -Method Head -TimeoutSec 20 -UseBasicParsing
"$($r.StatusCode) $($r.Headers['Content-Type'] -join ',') $($r.Headers['Content-Length'] -join ',')"
Start-Sleep -Milliseconds 1050
```

## 5. 数据质量教训（本轮踩到的）

### 5.1 榜单抓取要按「整行」评估可靠性，不要按单元格改错

`docs/全网玄幻榜单调研-20260826.md:170` 一行同时产出了三个错误：《诸天领主》作者错记烟雨江南（实为懒鸟）、《苟在初圣魔门当人材》作者错记三行的书哟（实为鹤守月满池）、以及一个**查无实据的书名**「进化的高武时代」。

**发现同一行有两处以上错误时，应判整行不可信并重抓，而不是逐个打补丁。** 选题库第 50 行《武圣》、第 52 行《一龙之力》后来也发现书名被截断、作者张冠李戴，属同类问题。

### 5.2 「同一作者有两本书」会被误判成「字段错位」

两者现象相似（榜单上作者名与预期不符），但成因和修法完全相反：字段错位要修抓取脚本，认错作者要修数据。**判别方法：去作者页看这两本书是不是都挂在他名下。**

### 5.3 平台分类 ≠ 题材

《急急如律令》是纯民俗灵异内容却挂在「科幻·进化变异」（这是起点诡异流的传统归属，不是错挂）。因此**不能只凭平台分类判断题材归属**——《廓晋》挂「历史·两晋隋唐」，但是否属于玄幻盘仍需看内容标签再定，本轮标为 `待定`。

### 5.4 书名要以平台为准

《我的魔法没有上限！》官方带感叹号，选题库漏了；《以一龙之力打倒整个世界！》在 QQ阅读侧简称《一龙之力》。写档案时以平台书页标题为准，简称写进备注。
